## Summary / 概览

`v2.1.4 Beta` syncs the latest Mac-side **AI Analysis backend-call fixes** into Windows, addressing reported GitHub issues that the AI backend call was broken with some providers/models. Three families: OpenAI reasoning-model compatibility, upstream error surfacing, and credential redaction. **Backend-heavy** — `astrostudyboot.jar` was rebuilt. Includes the 2.1.3 BaZi fix, the 2.1.2 AI rework, and the 2.1.1 clean-machine hardening.

`v2.1.4 Beta` 将 Mac 端最新的 **AI 分析后台调用修复** 同步到 Windows，解决 GitHub issues 反馈的「AI 后台调用有问题」。三类：OpenAI 推理模型兼容、上游错误透传、凭据脱敏。**以后端为主** —— 已重建 `astrostudyboot.jar`。

## What Changed / 本轮重点

- **A — OpenAI reasoning-model compatibility / 参数兼容** (`AIAnalysisProxyService.java`): new `isOpenAIReasoningModel` (matches `gpt-5.x`/`gpt-6`/`o1`/`o3`/`o4`, stripping any `provider/` prefix so `openai/gpt-5` works). `buildOpenAIChatBody` omits `temperature` and uses `max_completion_tokens` for these models; other models (e.g. `gpt-4.1`) unchanged.
- **B — Upstream error surfacing / 错误透传**: backend `ensureSuccess` reads the upstream error body (`readErrorBody`, truncated) and merges it into the `ErrorCodeException`; the frontend (`AIAnalysisMain.js`) handles a streamed `error` event and shows the real reason (`⚠️ <message>`) instead of the generic "模型未返回可用内容".
- **C — Credential redaction / 凭据脱敏** (`HttpUriRequestHystrixCommand.java`, shared `boundless` lib): `redactSensitiveHeaders` masks `Authorization`/`x-api-key`/`api-key`/`x-goog-api-key`/`cookie`/`proxy-authorization`/`localip` as `***redacted***` in error info; `stripQuery` removes `?key=` from logged URLs (e.g. Gemini keys).

## Jar rebuild (required — backend Java changed) / 重建 jar

`AIAnalysisProxyService` is in module `astrostudy`; `HttpUriRequestHystrixCommand` is in the shared `boundless` lib. No root reactor pom, fixed versions (boundless `1.2.1.2`, astrostudy/astrostudyboot `1.0.0`). Built with the bundled Maven + JDK 17:

```
mvn -o -f boundless/pom.xml  install -DskipTests
mvn -o -f astrostudy/pom.xml install -DskipTests
mvn -o -f astrostudyboot/pom.xml clean package -DskipTests   # clean required
```

Verified the fat jar contains the change: `BOOT-INF/lib/astrostudy-1.0.0.jar` → `AIAnalysisProxyService.class` has `max_completion_tokens`; `BOOT-INF/lib/boundless-1.2.1.2.jar` → `HttpUriRequestHystrixCommand.class` has `redacted`. Staged into `runtime/windows/bundle/astrostudyboot.jar` (the packaged jar re-verified to carry both).
