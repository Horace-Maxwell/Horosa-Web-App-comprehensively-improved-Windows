## Summary / 概览

`v2.2.0 Beta` syncs a batch of Mac-side **feature** work — two new 数算 methods (邵子参评数 / 河洛理数), harmonic-chart (调波盘) rendering, a full **React rewrite of the Feng Shui 纳气盘**, and an AI model-selection fix — and **batches in a Windows-side fix for GitHub issue #7** (app couldn't launch: `spawn tar ENOENT`). Backend Java changed (AI model hardening), so `astrostudyboot.jar` was rebuilt.

`v2.2.0 Beta` 同步 Mac 端一批**功能更新**（数算 邵子参评数/河洛理数、调波盘绘制、风水纳气盘 React 重写、AI 模型选择修复），并合入 Windows 侧 **issue #7 修复**（`spawn tar ENOENT` 导致装好打不开）。含后端 Java 改动 → 重建 `astrostudyboot.jar`。

> **Patch (2026-05-27 · 覆盖原 v2.2.0 / overwrites the original v2.2.0, same version):** 河洛理数流年算法按典籍重写——初版 `liuNian` 动爻位写死「从初爻数」，只在元堂=上九时偶合，其余大限流年全错；改为从上一年动爻**链式累变**（阳爻含首年/第二三年应爻规则）。仅前端 `utils/heluoLocal.js`（无 Java，不重编 jar）；`_heluoTest.mjs` 断言 59→72 全过。对应 Mac `2ade4c6`（Mac 亦在此 commit 打 v2.2.0 tag）；Windows 端原地覆盖 v2.2.0（移 tag + 覆盖资产）。

## What Changed / 本轮重点

**Mac-side (synced, Mac main `0ac85f0` / v2.2.0):**
- **数算 · 邵子参评数（canping）+ 河洛理数（heluo）** — new front-end-only techniques in the 数算 rail (`components/shusuan/{CanPingMain,HeLuoMain}.js`, `utils/{canpingLocal,heluoLocal}.js`, `utils/data/*.json`, wired in `components/kinastro/KinAstroMain.js`). Four pillars come from `utils/baziLunarLocal.js` — no kentang/Python backend.
- **调波盘绘制（harmonic）** — Python `astropy/astrostudy/{thirteenthchart,astroextra}.py` (`HarmonicChart` + `build_harmonic` returns a full chart); frontend `components/auxchart/{AstroHarmonicLab,AuxChartMain}.js`.
- **风水纳气盘 iframe → React** — new `components/fengshui/fengshuiEngine.js` (framework-agnostic canvas engine) + rewritten `components/fengshui/FengShuiMain.js` (Antd + `<canvas>`, ResizeObserver, AI snapshot); iframe deleted; `app.less` `:global{.horosa-fengshui-*}` layout + light/dark.
- **AI 模型选择修复** — `utils/aiAnalysisProviders.js` (Gemini `defaultChatModels`), `components/aianalysis/AIAnalysisMain.js` (`normalizeProfileChatModels`, test-connection uses the selected chat model), `utils/{aiAnalysisContext,aiExport}.js`; backend `AIAnalysisProxyService.java` defensively rejects an embedding model used as chat (`isEmbeddingModel` → 580014).

**Windows-side (batched in — GitHub issue #7):**
- **`spawn tar ENOENT` → app can't launch** (`service-manager.js`): payload extraction now resolves the OS tar to an absolute path (`%SystemRoot%\System32\tar.exe`) instead of a bare `tar` that relies on PATH/PATHEXT resolution (which ENOENT'd on the reporter's machine). New `resolveTarExe()` + actionable error.

机制细节 / mechanism: [`shusuan-canping-heluo-v2.1.9.md`](../shusuan-canping-heluo-v2.1.9.md), [`harmonic-chart-v2.1.9.md`](../harmonic-chart-v2.1.9.md), [`fengshui-react-rewrite-v2.1.9.md`](../fengshui-react-rewrite-v2.1.9.md), [`ai-model-selection-fix.md`](../ai-model-selection-fix.md). (Mac dev-named the first three `-v2.1.9`; they are this 2.2.0 release.)
